## 2026-10-15 — 1.3 Прячем в приложении то, что нужно только сайту
**Что сделал:** в начале `ui/index.html` завёл флаг `IS_DESKTOP = !!window.__TAURI__`. В приложении он `true`: на `<html>` вешается класс `desktop`, и CSS прячет фото-фон `.bg` и подпись `.credit`; карточка «Установить» и пункт меню «Установить как приложение» не показываются; service worker не регистрируется; `<link rel="manifest">` теперь добавляется скриптом только на сайте. Чтобы `window.__TAURI__` вообще появился, включил в `tauri.conf.json` `"withGlobalTauri": true`.
**Зачем:** приложению не нужна установка как PWA, а фон по плану будет прозрачным. Через флаг, а не удалением кусков, — чтобы файл можно было без правок положить обратно на сайт: там всё работает как раньше.
**Файлы:** `ui/index.html`, `src-tauri/tauri.conf.json`.
**Как посмотреть:** `cargo tauri dev` — фото, подписи и карточки нет. Открыть `ui/index.html` с сайта — всё на месте.
**Новые слова:** `withGlobalTauri` — настройка Tauri, которая кладёт в окно объект `window.__TAURI__` с функциями для связи с Rust. Нам он нужен, потому что у нас нет сборщика (npm/Vite), через который обычно подключают JS-библиотеку Tauri.
**Перенести на сайт:** флаг `IS_DESKTOP` и манифест через скрипт — сайту безвредно, можно перенести, чтобы файлы не расходились.

## 2026-10-15 — 2.2 Прозрачное окно
**Что сделал:** в `tauri.conf.json` включил `"transparent": true` и выключил `"shadow"`, а в `ui/index.html` для приложения сделал фон страницы прозрачным и отступ 8px (под тень окон плеера). Окно само подгоняет свою высоту под плеер: `ResizeObserver` следит за `.amp` и вызывает `setSize` (для этого право `core:window:allow-set-size`). Ручной ресайз выключил (`"resizable": false`), ширина фиксирована 476 = 460 плеер + 2×8.
**Зачем:** на рабочем столе должны быть видны только окна плеера, как у Winamp. Тень Windows (`shadow`) у безрамочного окна рисует прямоугольную каёмку — она бы выдала границы окна. Подгонка размера нужна потому, что прозрачные места окна в Windows всё равно ловят клики: без неё под свёрнутым в shade плейлистом остался бы невидимый «кусок стекла», через который не кликнуть по рабочему столу.
**Файлы:** `src-tauri/tauri.conf.json`, `src-tauri/capabilities/default.json`, `ui/index.html`.
**Как посмотреть:** `cargo tauri dev` → плеер лежит прямо на рабочем столе; двойной клик по заголовку плейлиста → окно ужимается, рабочий стол под ним кликается.
**Новые слова:** `ResizeObserver` — браузерный «наблюдатель», который вызывает функцию, когда меняется размер элемента. `LogicalSize` — размер в «логических» пикселях: Tauri сам умножит его на масштаб экрана (125%, 150%…), и окно будет одинаковым на любом мониторе.
**Заметка к 2.4:** размер окна теперь задаёт сам плеер, так что запоминать нужно только позицию.

## 2026-10-15 — 3.1 Иконка в трее
**Что сделал:** первый настоящий Rust-код, модуль `src-tauri/src/tray.rs`. Он ставит иконку в трей с меню «Играть / Пауза», «Следующий канал», «Предыдущий канал», «Показать», «Выход». Левый клик по иконке возвращает окно. Команды плеера Rust передаёт в окно событием `tray-action`, а JS вызывает готовые `play()`/`pause()`/`step()`. В Options появилась галочка «Закрывать в трей» (по умолчанию включена): `×` и Alt+F4 прячут окно, музыка играет дальше. У `tauri` включил встроенную функцию `tray-icon`, новых крейтов нет. Права окна: `allow-hide`, `allow-destroy`. Написал 3 теста на разбор пунктов меню.
**Зачем:** плеер радио обычно играет в фоне, и окно не должно мешать. Логику плеера не дублируем в Rust: она уже есть в JS, Rust только передаёт сигнал.
**Файлы:** `src-tauri/src/tray.rs`, `src-tauri/src/lib.rs`, `src-tauri/Cargo.toml`, `src-tauri/capabilities/default.json`, `ui/index.html`.
**Как посмотреть:** `cargo tauri dev` → иконка в трее (может прятаться под стрелкой ^) → правый клик. Тесты: `cargo test` в `src-tauri`.
**Новые слова:**
- `mod tray;` — подключает модуль из файла `tray.rs`. Модуль — отдельная «комната» кода; что в ней не помечено `pub`, снаружи не видно (`create` — `pub`, остальное — внутреннее).
- `enum` — тип «одно из нескольких»: `TrayAction` бывает `Player(...)`, `Show` или `Quit`. `Player("next")` — вариант, который несёт внутри данные.
- `match` — разбор по вариантам; компилятор заставит учесть все случаи, поэтому есть ветка `_ => None` «всё остальное».
- `Option<T>` — «значение или ничего»: `Some(x)` или `None`. В Rust нет `null`, вместо него — `Option`, и забыть проверку нельзя.
- `Result` и `?` — функция возвращает «успех или ошибку»; `?` после вызова значит «если ошибка — сразу вернуть её наверх». Так `create` отдаёт ошибку в `setup`, а не роняет программу.
- `if let` / `let ... else` — короткий `match` на один вариант: «если окно нашлось — работаем, иначе выходим».
- `|app, event| ...` — замыкание (closure), маленькая безымянная функция. Её отдаём Tauri, и он вызовет её, когда кликнут по меню.
- `&` — «одолжить, а не отдать» (заимствование): `&AppHandle` значит, что функция только пользуется приложением, а владеет им по-прежнему Tauri.
- `#[cfg(test)]`, `#[test]` — код тестов; он собирается только при `cargo test` и в готовый `.exe` не попадает.
- `emit_to` — отправить событие из Rust в конкретное окно; в JS его ловит `__TAURI__.event.listen`.

## 2026-10-15 — 3.2 Глобальные медиаклавиши
**Что сделал:** подключил согласованный плагин `tauri-plugin-global-shortcut` и написал модуль `src-tauri/src/media_keys.rs`. Он регистрирует в Windows четыре медиаклавиши: Play/Pause, Next, Prev, Stop. По нажатию Rust шлёт плееру команду. Отправку команд из трея и с клавиш свёл в одну функцию `send_player_command` в `lib.rs`, событие переименовал из `tray-action` в общее `player-action`. В JS добавил команду `stop`. Действие «сон» идёт тем же путём, но вживую не проверялось. **Реальное выключение и сон проверяет только владелец руками**, в релизной сборке (пункт 6.1).

**Новые слова:**
- `#[tauri::command]` — превращает обычную Rust-функцию в команду, которую JS вызывает через `__TAURI__.core.invoke('system_action', { action })`. Список команд отдаём Tauri в `generate_handler![...]`.
- `impl PowerAction { ... }` — блок методов типа: `PowerAction::parse(...)`, `action.command_line()`. `Self` внутри — «этот самый тип».
- `Result<String, String>` у команды — в JS это `Promise`: `Ok` приходит в `.then`, `Err` — в обработчик ошибки.
- `.map_err(...)` — переделать ошибку в другую (тут — в понятный текст), прежде чем отдать её через `?`.

## 2026-10-15 — 3.5 Автозапуск с Windows
**Что сделал:** подключил согласованный плагин `tauri-plugin-autostart` и сделал две Rust-команды в `src-tauri/src/autostart.rs`: `autostart_enabled` (включён ли) и `set_autostart` (включить/выключить). В Options появился пункт «Запускать вместе с Windows», по умолчанию выключен.

## 2026-10-15 — 4.1 Настройки в файле вместо localStorage
**Что сделал:** в приложении все настройки плеера (эквалайзер, тема, избранное, лайки, громкость, позиция окна, галочки) теперь живут в файле `%APPDATA%\ru.deemmoor.somaamp\settings.json`. За файл отвечает Rust-модуль `src-tauri/src/settings.rs`: чтение, «атомарная» запись (сначала `.tmp`, потом подмена) и команды `settings_set` / `settings_import`. Главное окно теперь создаёт Rust (`create_main_window` в `lib.rs`, в конфиге у окна `"create": false`). Так он успевает до запуска страницы положить настройки в `window.__SOMA_SETTINGS__`. В JS объект `store` на десктопе берёт настройки оттуда, а при записи вызывает Rust. При первом запуске всё старое из `localStorage` переносится в файл. Тестов на чтение/запись 6, всего 17.
**Зачем:** `localStorage` спрятан в папке WebView2: его не видно, не сохранить в бэкап и легко потерять при переустановке. Файл настроек лежит на виду. Окно создаёт Rust, потому что вызов Rust из JS всегда асинхронный, а плеер читает настройки сразу при старте. Положить их заранее проще, чем переписывать весь плеер на ожидание. Файл — простой словарь «ключ → значение»: какие настройки бывают, решает JS, иначе схему пришлось бы держать в двух местах. Атомарная запись важна из-за таймера выключения: полуписаный файл после внезапного выключения — это потерянные лайки. Битый файл не затирается, а откладывается как `settings.json.broken`. `localStorage` после переноса не чистил: это лишний риск без пользы.
**Проверено:** перенос из `localStorage` (тема, EQ, позиция, галочки попали в файл); смена темы, звёздочки и лайк → записались в файл → после перезапуска всё на месте (проверил владелец).
**Файлы:** `src-tauri/src/settings.rs`, `src-tauri/src/lib.rs`, `src-tauri/tauri.conf.json`, `ui/index.html`.
**Как посмотреть:** открыть `%APPDATA%\ru.deemmoor.somaamp\settings.json` в блокноте, поменять что-нибудь в плеере, открыть файл снова.
**Новые слова:**
- `serde_json::Value` / `Map<String, Value>` — «любое JSON-значение» и «словарь из них». Удобно, когда схему данных определяет не Rust.
- `type Settings = ...` — псевдоним типа: короткое имя для длинного.
- `Mutex` — замок на данные: пока одна команда меняет настройки, другая ждёт. `lock()` возвращает «ключ» (`MutexGuard`); замок открывается сам, когда ключ выходит из области видимости.
- `app.manage(...)` / `State<SettingsStore>` — положить объект в общее хранилище Tauri и получить его в любой команде, просто указав параметр.
- `Option::unwrap_or_default()` — «значение, а если `None` — пустое по умолчанию».
- `match` с `Err(err) if err.kind() == NotFound` — ветка с условием: «ошибка, но именно "файла нет"».
- `.entry(key).or_insert(value)` — вставить, только если такого ключа ещё нет.
- `Box<dyn std::error::Error>` — «любая ошибка»: удобно, когда в одной функции ошибки разных типов, и все их пропускает `?`.
- `initialization_script` — JS, который Tauri выполняет в окне раньше скриптов самой страницы.

## 2026-10-15 — 6.1 (часть 1) Сборка и починка звука в установленной программе
**Что сделал:** `cargo tauri build` собирает два установщика: `Soma Amp_0.1.0_x64-setup.exe` (NSIS, на русском, ставится для текущего пользователя в `%LOCALAPPDATA%\Soma Amp` без прав администратора — решение владельца) и `Soma Amp_0.1.0_x64_ru-RU.msi`. Серверы потоков SomaFM отвечают **403** странице с `http://tauri.localhost` (так открывается любая собранная Tauri-программа) и с `http://localhost:1430`, а странице с `http://127.0.0.1:1430` — **200**. Выяснилось, что `cargo tauri dev` всё это время показывал плеер со своего сервера `http://127.0.0.1:1430`. - Как только команды перечислены в `build.rs` (`AppManifest`), Tauri проверяет права на них и для локальной страницы, поэтому разрешения `allow-...` добавлены и в `default.json`.
